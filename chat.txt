5. 🚨 Evidence authorization needs fixing

This is one of the biggest actual security issues I found.

get_all_evidence() does:

evidence_list = db.query(Evidence).all()

That means an authenticated user can potentially receive evidence from all cases.

The comment says:

List all accessible evidence.

But the query doesn't actually enforce accessibility.

That's inconsistent with your case-isolation architecture.

It should instead effectively be:

INVESTIGATOR
    ↓
only evidence belonging to their cases

SUPERVISOR
    ↓
all authorized cases

ADMIN
    ↓
all

The same access-control helper should be reused everywhere.

6. 🚨 There is a serious case-ID fallback problem

In the graph router:

if not case:
    case = db.query(Case).first()

That's dangerous.

If someone requests an invalid case ID, instead of:

404 Case Not Found

the system can effectively fall back to the first case.

That's exactly the opposite of strict case isolation.

Same pattern appears in evidence handling.

Never do this
if invalid_case:
    return first_case

Instead:

raise HTTPException(
    status_code=404,
    detail="Case not found"
)

This should be fixed across the entire backend.

7. 🚨 AI RAG isn't actually doing semantic retrieval yet

This is probably the most important AI architecture improvement.

You calculate:

The query is effectively:

MATCH (n)

LIMIT 30

So the AI gets essentially:

"Here are the first 30 nodes."

rather than:

"Here are the graph facts relevant to the investigator's question."

That's not true RAG yet.

10. Entity resolution is conceptually good but technically needs improvement

This is the second major ML issue.

You calculate:

Lexical similarity
+
Structural similarity

Good.

But your structural similarity compares:

candidate neighbour IDs

with:

existing Neo4j neighbour IDs

The candidate IDs come from the newly extracted document.

Those IDs generally won't be canonical IDs from Neo4j.

So:

Phone_9876543210

in the new document may be compared against:

Phone_a73f...

or some other canonical identifier.

That makes the structural score much less meaningful than it appears.

13. Outbox is good, but your idempotency mechanism isn't actually implemented

You calculate:

idemp_key = hashlib.sha256(...)

but don't store it.

So the code claims to have idempotency, but the database doesn't enforce it.

That's an important distinction.

Better

Add:

idempotency_key

to OutboxEvent.

Then:

UNIQUE(idempotency_key)

Now retries can't generate duplicate events.

14. Neo4j schema has an architectural inconsistency

You use:

CREATE CONSTRAINT person_id
...
REQUIRE n.id IS UNIQUE

but your graph operations use:

MERGE (n:Person {id: $id, case_id: $case_id})

Meaning you're logically saying:

identity = id + case_id

but your Neo4j constraint says:

identity = id

Those two models conflict.

We need to decide what CRIMENET's identity model is.

I recommend

Canonical entity IDs should be globally unique.

Then:

entity_id
case_id

are separate concepts.

That actually helps entity resolution across evidence while still controlling case access.
