1. The biggest discovery

The files in:

backend/scripts/demo_data/

are locally authored demonstration data.

For example:

FIR_InLegalNER_Dossier.txt

It contains:

VIKRAM MEHTA @ "VICKY HAWALA"

and specific invented details such as:

Passport numbers
Aadhaar number
Hotel Oberoi Trident meeting
Mumbai Port coordinates
Zenith Maritime Logistics
HSBC account
Hawala transfer
specific accused persons

This is clearly a constructed investigation scenario.

Likewise:

CDR_Telecom_Matrix.csv

contains exactly 10 calls involving the same characters and phone numbers from the FIR.

And:

Hawala_AML_Ledger.csv

contains exactly 6 transactions connecting the same investigation entities.

That's actually useful for a controlled test — but it is not an imported copy of Telecom Italia or IBM AML.

3. There is an even bigger problem with the benchmark

I inspected:

ml/evaluation/benchmark_suite.py

and found several metrics that aren't actually being empirically measured.

For example:

er_metrics = {
    "Collision Candidates Identified": len(items),
    "Automated Merge Precision": 94.2,
    "False Merge Rate (Protected by Review Queue)": 0.0,
    "False Split Rate": 5.8
}

Those numbers are literally constants.

So:

Automated Merge Precision = 94.2%

is not calculated from the current experiment.

And:

False Split Rate = 5.8%

is also not calculated.

4. The hallucination metric has the same issue

The benchmark does:

has_citations = "FIR" in ai_text or ...
grounding_score = 100.0 if has_citations else 92.5
hallucination_rate = 0.0

Therefore:

If the answer contains the word FIR, the benchmark can report 100% citation grounding.

And:

hallucination_rate = 0.0

is simply assigned.

That's not a hallucination evaluation.

We absolutely should fix this before showing benchmark numbers to judges.

5. The NER benchmark is better — but still not true NER evaluation

This part is more legitimate:

tp = sum(
    1 for name in lbl_gt
    if any(name in ex or ex in name for ex in lbl_extracted)
)

You're comparing expected entities against extracted graph nodes.

That's a reasonable end-to-end entity recovery test.

But it isn't conventional token-level NER evaluation because:

no BIO tagging
no token spans
no document-level annotation comparison
substring matching can create false matches
graph normalization happens before evaluation

So I'd rename it:

End-to-End Entity Recovery

rather than simply:

NER F1

until we build a proper annotated NER evaluation pipeline.
